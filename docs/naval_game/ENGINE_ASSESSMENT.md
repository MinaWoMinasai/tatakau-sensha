# 海戦ゲーム向けエンジン分析

作成日: 2026-07-06  
対象: `CG2_testPro`（DirectX 12 / C++20）  
方針: 現在の2Dシューティング・3Dアクション開発と共存し、既存機能を壊さず独立シーンとして追加する。

## 結論

このエンジンで、三人称視点のアーケード型3D海戦ゲームの試作は可能である。描画基盤を新規開発する必要はなく、8月末までの重点は「船の操作・砲撃・敵艦AI・ミッション成立」に置ける。

一方、現時点で海戦固有の機能（水面、艦艇の旋回、弾道砲撃、魚雷、複数砲塔、艦船設計、セーブ）は確認できない。9月末までに低価格作品として公開する場合、PSP版相当の物量を目標にせず、小規模な独自作品へ絞る必要がある。

## 確認できた基盤

| 領域 | 現状 | 海戦への用途 | 判定 |
|---|---|---|---|
| DirectX 12描画 | 3Dモデル、2Dスプライト、テクスチャ、Skybox | 艦艇、島、HUD、空と背景 | 流用可 |
| モデル読込 | OBJに加えてAssimp経由のGLTF/GLB、スキニング | 艦艇・砲塔・航空機の読込 | 流用可 |
| カメラ | 通常／デバッグカメラ、三人称カメラ実装例 | 艦尾追従、照準、観戦 | 流用可 |
| 入力 | キーボード、マウス、XInputゲームパッド | 操舵、照準、兵装切替 | 流用可 |
| シーン管理 | Factory方式で複数シーンを切替 | 母港、設計、戦闘、結果 | 流用可 |
| 衝突判定 | Sphere/Capsule、属性・マスク、AABB等の計算 | 砲弾、魚雷、艦艇、島 | 拡張して流用 |
| 弾・攻撃 | Bullet/Manager、複数攻撃の実装実績 | 砲弾プール、ダメージ処理 | 設計を分けて流用 |
| 敵AI | 状態遷移、回避、射線、A*実装例 | 接近、離脱、攻撃状態 | 海面用に再実装 |
| エフェクト | Particle、Trail、Ring、Cylinder、EffectSequencer | マズルフラッシュ、煙、爆発、水柱、航跡 | 強く流用可 |
| 画面効果 | Bloom、影、アウトライン等 | 着弾・爆発の強調 | 流用可 |
| 音声 | Audio/AudioManager | 砲撃、着弾、警報、BGM | 流用可 |
| UI・文字 | Sprite、TextRenderer/TextLabel | HP、速度、装填、目標、結果 | 流用可 |
| レベルデータ | JSONのObject/SpawnArea/BossPhase/Balance | ミッション配置・増援・ボス段階 | 強く流用可 |
| 調整ツール | ImGuiとJSON設定、レベル補助ツール | 射程、装填、敵配置の反復調整 | 強く流用可 |

## 実装例から分かる成熟度

- `Action3DScene` に三人称移動、マウス／右スティックカメラ、ロックオン、HP、ボス状態遷移、勝敗がある。
- `GameScene` には大量のゲームプレイ、JSONバランス設定、レーザー、地雷、近接攻撃、弾道Trailなどの実装がある。
- `TestScene` には影、GPUスキニング、Skybox、各種エフェクトを個別検証する場がある。
- `LevelLoader` は通常オブジェクト、スポーン領域、ボスフェーズ、任意のカスタムプロパティを読める。

したがって「機能が存在する」だけでなく、戦闘ゲームへ組み合わせた実績もある。ただし、`GameScene` は非常に大きく、多数の責務を抱えているため、海戦機能をここへ直接追加すると既存ゲームとの干渉と保守コストが増える。

## 推奨する共存構成

新しい海戦作品は `game/naval/` 以下へ閉じ、既存の `GameScene`、`Action3DScene`、Player/Enemyを直接改造しない。

```text
game/naval/
  data/       艦・兵装・ミッションの定義と読込
  actor/      PlayerShip、EnemyShip、Turret、Projectile
  combat/     照準、射撃管制、ダメージ、装填
  ai/         敵艦の状態遷移と操船
  mission/    目標、増援、勝敗、報酬
  scene/      NavalTitle、NavalPort、NavalBattle、NavalResult
  ui/         HUD、艦装画面
```

エンジン共通層へ移すのは、海戦側で実証して再利用価値が明確になった機能だけにする。初期段階では既存ゲーム固有クラスの継承より、描画・入力・音声などエンジンAPIの利用を優先する。

## 新規に必要な主要機能

### 最優先（試作成立に必須）

1. 艦艇運動
   - 前後速力、舵角、速度に応じた旋回半径、加減速
   - 海面高度への拘束と簡易な横揺れ／縦揺れ
2. 砲塔と照準
   - 船体とは独立した砲塔旋回、仰角、射界制限
   - 目標地点またはロック対象への射撃
3. 弾道
   - 重力付き砲弾、着水／命中、爆発範囲
   - 装填時間、散布界、射程
4. 海戦向け当たり判定
   - 艦全体の簡易Compound判定、砲弾の高速移動対策
   - 島／浅瀬との衝突または進入禁止
5. 敵艦AI
   - 目標選択、射程維持、旋回、回避、射撃
6. ミッション
   - 撃沈、護衛／防衛の最低限、増援、成功／失敗、結果

### 販売候補版に必要

- 艦・兵装・ミッションのJSONデータ化
- 主砲／魚雷／対空またはミサイルの差別化
- 報酬、購入／装備、最低限のセーブ
- 設定画面、音量、解像度、キー／ゲームパッド表示
- チュートリアル、ポーズ、リトライ、エラー時の安全な復帰
- Releaseビルドでの性能・起動・配布物確認

### 今回は後回しにすべき項目

- 通信対戦・協力プレイ
- 本格的な流体シミュレーション
- 艦体上へ任意位置に全部品を置く完全自由設計
- 空母運用、潜水艦、航空機の本格AI
- 分岐する長編シナリオ
- 数百種類の実在艦・兵装
- 部位破壊や浸水の精密シミュレーション

## 技術上の注意点

| リスク | 内容 | 初期対策 |
|---|---|---|
| 大型シーン化 | `GameScene`と同様に1ファイルへ集中する可能性 | Naval側はActor/Combat/Mission/UIを最初から分離 |
| 高速砲弾のすり抜け | フレーム間で薄い艦を通過する | 前位置から現位置までSegment判定を使う |
| 多数の弾・敵 | 個別生成破棄とDraw Callが増える | 上限設定、プール、遠距離更新頻度低下 |
| 水表現 | 海面シェーダーを作り込み過ぎる | まず平面＋法線スクロール＋色／反射風表現 |
| 砲塔階層 | 親子Transformの扱いが不明確 | 船体行列×砲塔ローカル行列をNaval側で明示管理 |
| 調整量 | 武器数を増やすと指数的に検証が増える | 武器系統ごとに役割を固定し数を絞る |
| セーブ | 現状から汎用セーブ基盤を確認できない | バージョン付きJSON＋テンポラリ経由保存 |
| 既存変更との競合 | ワークツリーに未コミット変更が存在 | Navalを独立フォルダ化し既存ファイル編集を最小化 |

## 現時点の判定

- 8月末「遊べる戦闘試作」: **現実的**
- 9月末「無料公開できる小品」: **スコープ厳守なら現実的**
- 9月末「PSP版に近い艦船設計・物量・長編進行」: **非現実的**
- 9月末「有料販売」: **品質保証、素材権利、配布検証の余白が薄く高リスク**

最初の公開は無料デモまたは非常に小さな低価格作品とし、反応を見て艦船設計やキャンペーンを拡張するのが安全である。
