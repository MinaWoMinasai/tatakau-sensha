## 弾ブレ：確率の意味を修正する

見直し前の `Simulation::Fire()` は、biasを「外側の輪へ飛ぶ確率」として解釈し、内側と外側で異なる半径乱数を選び、さらに円周方向の乱数で上下左右へ飛ばしていた。これは公開パラメータの意味と一致しない独自近似だった。

資料の分布式は次の通り。`s` は最大拡散角、`b` はブレ値、`u` は0～1の一様乱数である。式は絶対偏差を返し、左右の符号は別の一様乱数で選ぶ。

```text
absoluteDegrees = s * pow(u, log(b) / log(0.5))
signedDegrees   = independentSign * absoluteDegrees
```

`b=0.5` では0～sの一様分布、bが小さいほど中央へ集中する。式から絶対偏差の中央値は `s*b` になる。biasは外周への命中確率ではない。

新しい [InkSpreadPattern.h](../project/game/ink/InkSpreadPattern.h) は、Simulationや乱数状態へ依存しない次のAPIを提供する。

```cpp
float ink::SampleSignedSpreadDegrees(float uniformMagnitude, float uniformSign,
                                    float spreadDegrees, float bias);
ink::Vec3 ink::PerturbHorizontal(ink::Vec3 direction, float deltaDegrees);
```

入力した乱数が同じなら同じ計算を行う。原作の乱数生成器、シード、乱数消費順まで一致するという意味ではない。C++標準数学関数を使うため、異なる実装間で浮動小数点のビット列が完全一致する保証も目的にしない。射撃用と塗り用の乱数列を分け、塗りの装飾を増やしても射撃結果を変えない設計は維持する。

有限の乱数値は0～1相当へ制限する。最大角が0以下、biasが0以下、非有限の入力は偏差0にする。biasが1以上なら偏差の絶対値をsにする。これは不正入力と数学上の端点に対するCG2の防御処理であり、通常の武器設定は0より大きく0.5以下を使う。

向きの変更は、正規化した照準方向をd、その水平右方向をrとして `d*cos(delta)+r*sin(delta)` を使う。世界Y軸まわりのyawだけを加えると、上下を向いたときに実際の角度偏差が小さくなるため避けた。この幾何の選択は公式修正内容と整合するCG2の実装であり、原作の回転行列を取得したという主張ではない。真上・真下では右方向が一意に定まらないため、X軸を安定した代用方向とする。独立した上下ブレ乱数は与えないが、横へ角度を振って再正規化する結果、Y成分がわずかに変わることはある。

## ジャンプ直後の初弾補正

見直し前はジャンプ時biasを `normalBias + (jumpMaximum - normalMaximum)*jumpFactor` としており、通常biasが0.01、通常最大0.25、ジャンプ最大0.40の場合、ジャンプ直後は0.16にしかならなかった。ジャンプ後も初弾が過度に中央へ集中する原因になる。

今回の小さな修正案は `normalBias + (jumpMaximum - normalBias)*jumpFactor` とし、ジャンプ直後を0.40へ合わせること。25F後に回復を開始し70Fで地上値へ戻す既存の時間と、4.86°／11.66°の最大拡散角を維持する。これは確認済みの端点へ補間を合わせる変更であり、原作の通常biasとジャンプbiasの内部的な合成順まで確定したものではない。

**単に地面から離れているかどうかへ条件を変更しない。** 解析者の説明では、ジャンプせず段差から歩いて落ちた場合は通常の拡散を維持できる。現在のジャンプ発生時刻に基づく処理はこの区別を残している。

## 再入力による連射間隔の短縮

見直し時の `Simulation::Step()` は、射撃ボタンの立ち上がりごとに `fireCooldown_` を初弾待機へ上書きしていた。直前の射撃の6F待機が残っていても、人型の3F待機へ短縮できるため、押す／離すを繰り返すと連射設定より速く撃てる。これは6Fという既存設定と実装の不整合であり、参考動画の計測から推定した問題ではない。

修正方針は、直前の射撃から次に撃てる時刻を維持し、初弾・形態変更の待機も満たすまで発射しないこと。残り時間と新しい待機の最大値を使うか、次回射撃可能時刻を別に持つ。人型初弾3F、イカからの初弾12F、射撃後の形態復帰制限4Fは既存調査の値を維持する。初弾待機がなくなる変更や、古い作品の11Fへ置き換える変更にはしない。

## 組み込み後に必要な確認

ヘッダー追加時点ではSimulationへの組み込みと最終テスト結果をこの文書で完了扱いにしない。担当側の実装報告で結果を確定する。

ヘッダー単独の確認はMSVC C++17、`/W4 /WX /O2` でコンパイル・実行済み。bias 0.01／0.25／0.40／0.50の中央値、各10,001点での単調性・左右対称・最大値、上下の照準と厳密な垂直方向、入力の端点・NaN・ゼロ方向の検査はすべてPASS。これは数学ヘルパーの検査結果であり、ゲーム全体の実行結果とは分ける。

- 分布：b=0.5が一様、b=0.25・0.01の絶対偏差中央値がs*b付近、左右が対称、最大偏差がs以内になる。
- 向き：水平だけでなく上下60°程度でも実際の角度偏差が同じになり、出力の長さが1になる。真上、真下、ゼロ方向、非有限値でもNaNを広げない。
- 時間：押しっぱなしと短い再入力の両方で6Fの間隔を守る。初弾3F／12Fと射撃後4Fを固定刻みの境界を含めて確認する。
- 状態：ジャンプ直後はジャンプ側の拡散とbiasへ移り、回復後は地上値へ戻る。歩いて段差から落ちるだけではジャンプ側へ移らない。
- 再現性：同じ入力・同じ射撃シードから同じ射線が出る。塗り側の乱数消費を変更しても射線が変わらない。

## 今回の小変更と分けて扱う不足

敵インクで移動やジャンプが鈍る処理と、イカ助走で得た水平速度を空中へ継承する処理は、別途確認する価値がある。公式履歴は敵インクのジャンプ低下を裏付けるが、具体的な倍率は載っていない。[のらまに本人による実演の解説](https://note.com/noramani_game/n/n879d3f875412) は助走ジャンプの飛距離差を示すが、CG2へそのまま写せる慣性係数を定義していない。[かなもじの弾道解析](https://note.com/kanamoji_1027/n/n20cb3c3fb251) は上昇中のプレイヤー速度が弾へ影響することにも触れているが、この資料だけから全ブキの継承係数を決めない。

可変ジャンプ、完全なイカロール／イカノボリ、壁ジャンプの入力条件やアーマーを、今回の射撃分布の修正へまとめて追加する必要はない。実装する場合は存在の確認と係数・発動条件の確認を分ける。

提供された参考動画の [コンタクトシート](../generated/ink_phase2/reference_contact.jpg) は視覚的に確認した。液滴のまとまり、局所的な反射、射撃中の姿勢は比較できる。一方、30fps録画と不明な入力履歴から3Fや12Fの遅延、正確なカメラ定数、乱数分布を測定したとは扱わない。原作動画との定性的比較と、CG2の同一入力による再現テストは目的が異なる。
