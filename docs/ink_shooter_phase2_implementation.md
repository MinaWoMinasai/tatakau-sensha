2026-09-12。既存の「撃つ → 塗る → 自インクへ潜る → 移動・補給 → 人型へ戻って撃つ」を維持し、塗りの形、液体の弾、材質、変身、三人称カメラを改善する。任天堂のモデル・ブラシ画像・アニメーション・音声・ゲームコードは使用していない。

レンダラーのC++構文検証とHLSLコンパイル、Simulationの追加回帰テスト、Development / ReleaseのフルビルドはPASS。最終材質で両構成の約45秒の実機検証デモを実行した。Releaseは起動時から45秒のプレイまで、Developmentは45秒のプレイと追加の起動時診断で、D3D12 Debug LayerのERROR 0／WARNING 0を確認した。 GPU based validationは無効で実施している。

## 2. 改善した項目と使い方

塗りの形と液体表現を中心に改善し、日本語の状態表示・操作案内・設定画面を追加する。基礎ループと120Hz固定Simulationは維持する。任意メッシュ対応や大型Particle Systemへの移行は行わない。

```powershell
# ワークスペースのルートから実行。先に対象構成をビルドする。
.\project\tools\run_ink_shooter.ps1

# 設定画面を開いて開始
.\project\tools\run_ink_shooter.ps1 -Settings

# シナリオごとに初期化する約45秒の検証デモ
.\project\tools\run_ink_shooter.ps1 -Validate

# 通常の操作デモ
.\project\tools\run_ink_shooter.ps1 -Demo
```

F1で日本語設定（Development）、Tabでマウス解放／操作復帰、F9でデモ、F10で比較画像を保存する。F10の保存先は[project/generated/ink_phase2](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/project/generated/ink_phase2)。起動スクリプトはビルドを実行しない。Tabは入力の解放であり、Simulation全体の停止ではない。

DevelopmentのImGuiは項目名・状態・説明を日本語化した。インク消費量は0.0092ではなく0.92％と表示し、カメラや塗りの形を調整できる。調査済みの基準値は通常読み取り専用で、実験用の変更を有効化した場合だけ編集する。メイリオ／MSゴシックとImGuiの字形範囲を照合し、設定画面の日本語330種類に欠落はなかった。

## 4. 塗り形状の変更

主着弾の長軸は、着弾直前の速度を面の接線方向へ射影して決める。法線をn、入射方向をdとして面に対する角度を`asin(abs(dot(d,n)))`で求める。面に沿う入射は0度、正対する入射は90度となる。射影がほぼゼロなら、安定した面内方向を使用する。

再確認したDepthScaleMin/Maxの1.31／2.24と、解析資料が説明する35度／10度の境界を用い、浅いほど長い主着弾を生成する。35度より正対する範囲はCG2独自に丸い形へ近づけ、90度で縦横比1となる。これは公開値から確認できる区間と、原作のブラシを持たない部分の近似を組み合わせたものである。[塗りパラメータの再調査と確度](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/docs/ink_shooter_phase2_research.md)

公開のWidthHalfを基準となる幅として保持し、完全に塗りつぶす中心部分の倍率は主着弾0.68、途中飛沫0.55、足元0.43として分ける。旧来の丸い膨らみを均等に並べる方式から、不均等な細い付加楕円と、浅い主着弾の先端、離れた小粒へ変更する。コア倍率・付加楕円の位置・粒の乱数分布はCG2の近似値である。

床・坂・壁へ同じ面内射影を適用する。壁だけ別の画面方向へ伸ばす処理は使わない。塗れない面ではCPU更新もGPU更新も拒否する。GPU専用のノイズで塗れる範囲を広げることはしない。

共有スタンプは面ID・中心・2つの半径・回転・チームを持ち、CPUとGPUが同じ回転楕円式を評価する。`PaintKind`は分類メタデータであり、GPUが別の範囲を推測する材料にはしない。

## 5. Paint Dropletと小粒の変更

| 種別 | ゲーム中の役割 | 今回の形と扱い |
| --- | --- | --- |
| Main | 主弾の着弾 | 入射方向へ伸びる中心、細い付加形状、小さな離れた粒 |
| Droplet | 飛行中に落ち、射線下の道をつなぐ | 主着弾より小さい中心。長軸の伸びも弱くする |
| Scatter | 主塗りの周囲の小さい汚れ | 主塗りから離れた小楕円。広い水たまりへまとめない |
| Foot | 射撃位置近くの道を補助 | 最初の飛沫と、乾いた足元へ生成する救済飛沫に役割を明示 |

通常の飛沫は引き続き距離の通過点から落下させ、掃引で最初に当たる面に塗る。壁を通過した位置や地下へ無条件に床塗りを投影しない。足元救済は接地中かつ足元が自インクでない場合、独自の4発ごとの条件で小さい落下飛沫を追加する。

公開値の`SpawnNum=1.5`、`SplitNum=8`、`SpawnBetweenLength=9.2`、`ForceSpawnNearestAddNumArray=[4]`を再照合して保持する。ただし現在の「最大8個」「0.95±14%の途中間隔」「乾いた足元へ4発ごとの救済」は、その内部アルゴリズムを解読した結果ではない。途中間隔は旧版のCG2近似値1.15から0.95へ調整し、小さくした飛沫の道のつながりを補う。公開値を換算した4.6は別フィールドのまま維持する。`[4]`がその救済条件を意味するとは断定しない。BreakFreeや落下高さの関連値も保持するが、完全な状態判定・補間規則まで実装済みとはしない。[公開値と未確認部分](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/docs/ink_shooter_phase2_research.md)

塗り形状・飛沫の乱数列を主弾の拡散乱数から分離した。ブラシの粒数や途中飛沫の設定を変えても、その後の主弾の拡散と飛行軌跡が変わらないことをテストする。

## 6. Projectile表示の変更

空中の弾・飛沫を、既存の細い線から`InkLiquidRenderer`の専用billboardへ置き換える。主弾は太い先端と細い後方を持つ涙滴、小さい落下飛沫は丸みの強い涙滴、着弾と銃口には短い付加形状を持つ液体の塊を使う。速度の画面内成分へ長軸を向け、横から見た高速弾を短く伸ばし、正面に近い弾は丸い形へ寄せる。

濃い中心、少し柔らかい縁、小さな弱いハイライトをシェーダーで描く。加算合成は使用せず、奥から手前へ並べた通常のアルファ合成と深度テストで描画する。半透明の四角形が後続の弾や地形を不正に隠さないよう、深度を書き込まない。

液体専用の1つのインスタンス描画にまとめ、最大4096個とする。インスタンスデータは1個64バイトで、GPUのアップロード領域は最大256KiB。テクスチャアセットや新しい大規模Particle Systemを必要としない。超過時は表示用の追加要求だけを落とし、弾道・塗り・ダメージには影響させない。

着弾イベントはSimulationから独立に受け取り、短い飛散と波紋へ変換する。これらの見た目の粒は追加の塗り判定を持たない。既存の照準先の小さい十字表示は用途が異なるため、線のまま残す。

## 7. インク材質と境界の変更

地形の顔料色は線形色空間で自色`(0.004, 0.39, 0.235)`、敵色`(0.48, 0.008, 0.145)`を基準とする。HUDの明るい表示色とは分ける。塗装部分のroughnessは0.30、非塗装部分は0.82。metallicは0を維持する。

ハイライトは`pow(N·H,64)×0.12`と`pow(N·H,18)×0.055`を組み合わせ、弱い視線依存項を添える。光源方向を`normalize(-0.22, 0.66, 0.72)`として床の観察角でも反射が見えるようにし、細かい法線変化の振幅を0.025とした。以前の強い白いハイライトや一様な明るいミント色を抑え、顔料の色の深みを残す。法線変化と縁の濃淡は陰影だけであり、所有者グリッドを変更しない。SSRに渡す塗装面の反射用マスクも0.06へ抑える。

**境界平滑化は表示専用。** 4つの近傍から、それぞれ「自色の被覆率」と「敵色の被覆率」を個別に補間する。格納されたチームIDの数値を線形補間して別チームへ丸める処理は行わない。たとえば敵色と未塗装の中間を自色と解釈することはない。タイル端の読み出しもそのタイル内へクランプし、隣の面から色を拾わない。

潜伏・遊泳・補給の判定は従来どおり512×512の離散所有者を読む。GPUマスクのalphaにあるチームIDも変えない。表示色の変化は境界付近の半画素程度に限られ、CPU判定をぼかして泳げる道を増やす機能ではない。設定の境界補間ON/OFFで、同じ塗りデータの見た目とGPU時間を比較できる。

既存のMRTは色`RGBA16F`、法線`RGBA16F`、材質`RGBA8`を維持する。地形描画は3つを正しい形式で更新する。深度を書かない一時的な液体表示では、既存CG2の半透明描画と同じく法線・材質の書き込みを無効にする。これによりSSAO/SSRが参照する不透明地形の深度と法線・材質の対応を保つ。

## 8. 変身表現の変更

人型から潜る際は横幅と縦の縮小を分け、身体をインク面へ少し沈める。遊泳時は従来より小さく扁平な独自モデルへ移り、床上の大きな球という印象を弱める。壁泳ぎ中は壁法線に姿勢を合わせる。人型へ戻るときは約0.2秒の短い縦方向の伸びを添える。

状態の切り替えには7個の小さい飛沫と波紋を付け、泳いでいる面の向きに波紋を配置する。飛沫と姿勢補間は描画側の演出であり、入力受理・実際の状態変更・速度・補給開始を演出の終了まで待たせない。既存の`formBlend`と120Hzのゲーム状態を基準に、表示だけを補間する。

検証デモでは自色遊泳の速度5.76、壁泳ぎ4.32、壁上端を越えて高さ6へ移ることを確認した。[床遊泳の画像](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/project/generated/ink_phase2/02_swim.png)と[壁泳ぎの画像](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/project/generated/ink_phase2/06_wall_swim.png)を最終材質でも保存した。床遊泳は旧版より小さい姿となり、波紋が面上に残る。

## 16. 次の優先改善項目と任意メッシュへの設計案

まずReleaseの実機確認と最終操作の追試を完了する。次の実装では、今回の画像・GPU時間を基準に、入射角・落下高さ別の塗り道と飛沫の配置、独自キャラクターの射撃・潜伏アニメーション、カメラの障害物付近の追従を優先する。未確定の飛沫内部アルゴリズムは、資料の根拠が得られた箇所から置き換える。

任意のステージモデルへの塗りは次段階の設計に留める。[各方式の比較](C:/Users/k024g/OneDrive/デスクトップ/自作エンジン2/docs/ink_shooter_phase2_research.md)では、次の経路を第一候補とする。

1. 衝突ヒットからメッシュID・三角形ID・重心座標・法線を返す。
2. 重複しない塗り用UVへ変換し、メッシュごとの小さい塗りテクスチャ、または共有UV atlasへ書く。
3. CPUも同じ塗りUVとスタンプで所有者を更新する。
4. UV島の余白・継ぎ目をまたぐ塗り・隣接三角形への再投影を検証する。
5. 大きいステージで必要になってから、world-space virtual textureやtiled world paintのページ割り当てへ進む。

三角形IDと重心座標だけでは塗りの保存先にならないため、UVまたはワールドの保存方式と組み合わせる。単純なXZ投影では上下に重なる床・橋・壁を区別できない。いずれの方式でも「衝突点を塗り座標へ変換する」役割を分離し、今回の弾道や武器基準を変えずに塗りの保存先を拡張する。
