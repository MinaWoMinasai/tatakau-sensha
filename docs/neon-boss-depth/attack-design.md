## Authority and entry

`Enemy` owns one XY floor position, radius, HP, death state, and encounter generation. The 3D body has no gameplay collider. Player projectiles, homing, Drone shots, melee, and explicit dash attacks target the existing floor core through existing attack/collision paths. Normal Player/Drone contact with the core is harmless; `CollisionManager` performs existing `TryDashImpact` first, then suppresses that ordinary core-body contact. Depth does not run Rival or Prototype AI in parallel. Their explicitly selected Developer fixtures retain those policies.

Ordinary expedition Boss rooms select Depth when `resources/configs/neonBossDepth.json` is enabled and the floor-cue renderer initializes. Legacy fixtures are explicitly excluded. Normal authored-room boss HP retains the existing expedition balance value, with source fallback 900; fixture HP is separately declared in fixture evidence. Intro locks gameplay input and core damage for 2.4 seconds. Enter/Space uses the scene's ordinary skip request, retaining a zero-combat-tick skip frame before the same Reposition state. The core is vulnerable in every nonterminal combat phase after Intro, including Airborne; visual height does not change attack reach.

## Default attack cycle and shapes

The deterministic cycle is Volley → Dive → Beam → Volley. Each attack follows Reposition → Telegraph → Locked → Airborne → Active → Recovery, except Beam moves directly from Locked to Active. Reposition lasts 0.60 seconds. All durations below are seconds; geometry is in existing world units.

| Attack | Telegraph | Locked | Airborne | Active | Recovery | Actual floor contract |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Volley | 0.85 | 0.30 | 0.55 | 0.35 | 1.00 | Three circles, radius 2.1; damage 12 per claimed circle contact |
| Dive | 0.80 | 0.35 | 0.45 | 0.20 | 1.30 | One circle, radius 3.4; damage 18 per claimed contact |
| Beam | 0.90 | 0.30 | skipped | 1.10 | 1.20 | Swept capsule, range 28, active half-width 0.8, sweep 1.2 radians; damage 9 per claimed contact |

The stored Beam Airborne duration defaults to 0.10 but is not visited by its phase transition. Dimensions, timing, damage, targets, and identity are copied into the committed value plan. Valid config reloads queue combat tuning for the next committed attack; they cannot rewrite an existing warning or active plan.

Volley places legal, separated circles around the captured player target, along the axis perpendicular to the core-to-target direction. Default center spacing is `2 × 2.1 + 1.6 = 5.8`. On the single Airborne→Active transition it emits one FloorArrival event per circle. There are no damaging airborne bullets or animated-joint colliders. A target may claim each circle only once during that attack's Active window; rendering the arrival repeatedly cannot emit another event or hit.

Dive captures a legal target shared by its landing circle and `coreTarget`. It limits travel to 12 units and requires a clear path for the core's conservative radius 2.30. During Airborne the single authoritative XY core moves from the committed start to target. `Stage::ResolveEnemyCollision` handles actual movement in axis substeps no larger than 0.35 unit. The landing event occurs once at Airborne→Active. The animated body's altitude never replaces the floor circle, HP, or position.

Beam stores 17 wall-clipped future warning capsules. Their shared conservative half-width is `0.8 + 28 × sin(1.2 / 32) ≈ 1.849754`, covering the continuously swept active band between samples. Active angle interpolates the same committed start/end angles. Its reach is capped by the shorter neighboring warning segments before actual clipping, and its half-width stays 0.8. Draw and damage use the stored clipped active segment; neither reconstructs a separate ray or guessed warning width.

## Walls and escape policy

The adapter copies actual Stage merged XY boxes once per encounter, bounded to 4096. Floor planning uses the existing 45×30 map grid and a bounded 1350-cell search. The current final-duel interior wall faces are X 21–67 and Y 15–43; radius checks require shapes to fit those faces and actual Stage blockers. Volley circles and Dive landings must be legal. The corrected real Enemy floor position after Reposition becomes the next plan's origin.

`ClipGroundBeam` expands blocking boxes by the capsule half-width plus 0.001 unit before clipping the centerline. This keeps the rounded beam end from reaching through a wall. An origin inside an expanded blocker is rejected instead of producing a damaging zero-length capsule. The same operation clips both each exact-width warning capsule and the active capsule.

Every plan must leave a reachable floor cell outside its entire warning danger region, including player radius plus 0.25 unit margin. The path budget remains `(Telegraph + Locked) × 6.0 − 0.5` units; no dash or favorable time scale is assumed. With default Beam timing this is 6.7 units. The planner does not shrink an unsafe configured hazard, ignore a wall, or hide its warning.

For Beam, the planner first tries a sweep centered on the captured player direction. If it fails the same escape test, it tries two more deterministic orientations with the captured direction at either sweep edge. Range, sweep angle, widths, sample count, clipping, and time budget remain unchanged. All three candidates can still be rejected. This repairs the observed core `(34,28)` / player `(26,28)` case: the archived actual 38-box room has no reachable exit for the centered band, while an edge sweep leaves an exit at `(26,32)` or `(26,24)`, four units away. The original failed evidence is preserved. The production C++ `CloseBeamKeepsEscapeAndFullWarning` regression passed for orientation selection, canonical clipping, continuous active-band warning containment, and no contact at the promised exit. Both 2400-frame `cycles_d` actual GPU fixture reruns also passed with phase-one and phase-two attack masks 7/7.

## Hits, phase two, and stopping

Only Active in a valid positive gameplay update permits a hazard contact. `Step` clamps a positive time step to 0.10 second and performs at most one phase transition, discarding any remaining spike time so newly shown warnings retain their duration. Zero, negative, or nonfinite updates close contact permission without advancing attack time. Death/abort still takes effect at zero time. Each committed attack has a fresh instance ID inside a monotonically increasing encounter generation; stale hit reports cannot match a reset encounter.

Volley and Dive allow one claim per target/circle per attack. Beam allows repeated claims for the same target only after its 0.45-second hit interval. A claim is not proof of damage: `Player::ReceiveHostileHazard` reuses existing dash/perfect-dodge, immunity, counter, mitigation, and lethal-damage handling, then returns actual HP loss. Accepted-hit telemetry increments only for a matching claim with positive actual HP loss. Normal accepted damage grants the existing 0.45-second immunity. Perfect dodge remains conditional on the existing ability and contact timing: `0.20 × power` seconds from dash start, capped at 0.30. The existing right-click dash lasts 0.30 second.

HP ratio at or below 0.50 latches phase two for the next committed attack. A warning already shown stays immutable. Phase-two Volley uses five circles of the same radius; Dive and Beam retain their default shapes/durations/damage. Recovery advances the attack cycle. HP zero immediately disables gameplay through the existing death path; Aborted/Defeated clears pending contacts and attack authority while the scene may retain visual death/dissolve presentation. Repeated draw calls cannot resume gameplay or create contact events.

## Three existing combat styles

Use WASD to move, mouse to aim, hold left click for the selected style's primary action, and right click for the existing dash/perfect-dodge input. Normal style choice uses 1 Shooter, 2 Drone, 3 Melee. Shops, purchased modules, repair costs, rewards, stamina, cooldowns, wall behavior, and actual death/retry remain the existing expedition rules.

| Style | Existing primary action | C++ base defaults before class/modules |
| --- | --- | --- |
| Shooter | Aim and shoot normal projectiles at the floor core | Damage 6; interval 0.30 s |
| Drone | Aim and command the actual companion attacks | Three base drones; damage 3; interval 0.50 s |
| Melee | Aim and perform the existing melee combo/slashes at the floor core | Damage profile 15.2; interval profile 0.33 s; range profile 4.3 |

All three base profiles start with HP 120, movement 0.23 unit per 60-FPS base frame, and max stamina 3. These are source defaults, not a promise that every evolved/purchased build has those exact live values. The runtime snapshot records actual current values. Depth mouse and Drone aiming map actual client coordinates to the render viewport, then solve floor Z=0 from the same displayed camera view-projection; invalid picks preserve the previous aim.
