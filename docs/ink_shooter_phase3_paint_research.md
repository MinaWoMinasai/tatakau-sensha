# 第3段階：飛沫の個数・位相・足元塗りの再調査

2026-09-12。対象は Splatoon 3 Ver.11.3.0 の対戦用スプラシューター。第2段階で使用した「各弾に最大8飛沫、毎回同じ最初の位置、主着弾に3小粒、乾いた足元へ4発ごと」の規則性を見直すための調査と設計記録である。

## 結論と確度

公開データは **SpawnNum=1.5、SplitNum=8、SpawnBetweenLength=9.2、SpawnNearestLength=1.2、ForceSpawnNearestAddNumArray=[4]** を保持している。しかし、これだけで乱数分布や位相の順序は復元できない。特に `SplitNum=8` を「毎回8個の飛沫」と扱う根拠はない。[Leanny の固定版11.3.0データ](https://raw.githubusercontent.com/Leanny/splat3/7280ff9cde8bb1c5dcef46c700c326471584d2e6/data/parameter/1130/weapon/WeaponShooterNormal.game__GameParameterTable.json)

Sendou の作者・寄稿者が公開しているパラメータ説明は、`SpawnNum` を各弾が途中に落とす飛沫数、`SpawnBetweenLength` をその飛沫間の距離と説明し、足元の塗りは別の制御であると区別する。説明は任天堂の更新情報とバージョン別データを突き合わせて再構成したものと明記されている。[Sendou の説明ソース、固定コミット](https://github.com/sendou-ink/sendou.ink/blob/873c5e941d58049f60de58b50bbc20ea81a04d9b/app/features/params/core/param-explanations.ts)

一方、解析者 XarrotD 自身の説明では、`SpawnNum`、`SplitNum`、足元配列の多くの意味が未解明として残る。Sendou の `SplitNum` 説明も足元への飛散の起こりやすさという概略で、実行順序や式を公開していない。[XarrotD のパラメータ調査ノート](https://splatoonwiki.org/wiki/User:XarrotD/paramtable)

したがって今回は、**公開値に対応する少数の途中飛沫と、小数の個数を保つ予算、射撃間で位置をずらす位相**を組み合わせる。ただし位相順序・小数処理・揺らぎ・足元救済条件の実装はCG2の近似である。「原作の内部アルゴリズムを解読した」「原作は毎回独立乱数で1個または2個を選ぶ」とは報告しない。

## 原作資料とCG2の選択を分ける

| 項目 | 確認できたこと | 今回の実装上の選択 |
| --- | --- | --- |
| SpawnNum | JSONの生値1.5。Sendouでは途中飛沫数と説明 | 小数予算を持ち、初期状態では1個・2個の割当てを繰り返す。正確な原作の丸め方とは断定しない |
| SplitNum | 生値8。原作の位相テーブルや選択順は未確認 | 8つの距離区画を一巡する。初回にCG2独自乱数で順序を選び、以後はその順序を保つ |
| SpawnBetweenLength | 生値9.2。途中飛沫間の距離という説明がある | 縮尺0.5により同一弾の追加飛沫は4.6離す |
| SpawnNearestLength | 生値1.2 | 最初に割り当て得る距離を0.6にする。位相によってそこから前へずらす |
| ForceSpawnNearestAddNumArray | 生値[4]。細かな条件と配列の扱いを確定する一次資料は未確認 | 生値から直接判定を作らない。乾いた足元・接地中に限る別の救済条件を使用 |
| 各飛沫の幅・横ずれ | 公開幅の参照値は維持 | 同じ弾の幅には相関を持たせ、幅0.92～1.12倍、横ずれ±0.06の範囲で変える |
| 小粒 | 主着弾周りの原作の正確な粒数分布は未確認 | 各弾の計画に1～5個を割り当てる。使用するスタンプの形は引き続きCG2独自 |
| 足元救済 | 原作の足元塗りは途中飛沫と別に制御される | 乾いた状態の射撃が3～4回続いたときに実際の落下飛沫を出す。位置と幅も狭い範囲で変える |

この表の生値は固定版の武器JSON、意味の補助説明は公開説明ソースに基づく。距離の0.5換算はCG2独自の縮尺であり、実世界のメートル換算ではない。[武器JSON](https://raw.githubusercontent.com/Leanny/splat3/7280ff9cde8bb1c5dcef46c700c326471584d2e6/data/parameter/1130/weapon/WeaponShooterNormal.game__GameParameterTable.json)、[説明ソース](https://github.com/sendou-ink/sendou.ink/blob/873c5e941d58049f60de58b50bbc20ea81a04d9b/app/features/params/core/param-explanations.ts)

日本語の検証Wikiにも、射撃の巡回と足元配列、0.5個なら2発に1個という説明が見つかった。ただし元のコード、乱数、完全な位相順序を示す一次検証への導線を確認できなかったため、上記アルゴリズムを確定する根拠としては採用していない。資料の記述と実装の確度を混同しない。[追加調査の対象ページ](https://wikiwiki.jp/splatoon3mix/%E6%A4%9C%E8%A8%BC/%E3%83%91%E3%83%A9%E3%83%A1%E3%83%BC%E3%82%BF%E6%83%85%E5%A0%B1/%E3%83%A1%E3%82%A4%E3%83%B3)

## 新しい生成計画の契約

`project/game/ink/InkEmissionPattern.h` はDirectXや地形に依存しない計画器である。`EmissionPattern::NextShot` は、実際に主弾を発射したときに一度だけ呼ぶ。戻り値の `ShotEmissionPlan` をその弾に保存し、弾が計画距離を通過したときだけ飛沫を出す。描画フレームや着弾の順序によって再抽選しない。

距離区画の間隔は `4.6 / 8 = 0.575`。最初の距離は `0.6 + 0.575 × (位相 + 小さな揺らぎ)` とし、同一弾の次の飛沫はさらに4.6先に置く。初回に選んだ巡回順序を保つことで、射撃を途中から数えた場合も、連続8発には必ず全区画が含まれる。位置・幅・横ずれ・小粒数は弾ごとに変わる。揺らぎは区画幅の±12％以内で、近端を0.6未満へ動かさない。これはCG2の分布設計で、Nintendoの位相テーブルではない。

最初の試作は巡回ごとに順序を再抽選していたが、巡回の途中から撃ち始めた場合、区画の重複と欠落により道へ乾いた隙間が残ることを実際の所有者マスクで検出した。ブラシを大きくするのではなく、順序を固定してこの欠落を解消した。規則性をなくすことよりも、射撃の積み重ねで歩ける道が形成されることを優先した修正である。

足元救済は接地・乾いた足元を呼び出し元で判定し、最大4回の乾いた射撃までに発生する。原作の配列[4]を「4発に1回」という条件へ直接読み替えない。救済位置はプレイヤーの前0.34～0.39、右0.07～0.13、幅1.02～1.16倍に制限する。足元と近端の道を両方つなぎやすくするためのCG2の範囲であり、塗装されていない地形へ無条件に塗りを投影する機能ではない。

## 割当て数と実際の飛沫数が異なる理由

`requestedDropCount` は小数予算が要求した個数、`count` は計画距離の上限以内に残った個数である。さらに実行時は、その距離へ達する前に主弾が壁や標的へ当たる場合がある。遮蔽物の向こうに飛沫を出したり、原作の数値を合わせるために寿命や射程を延ばしたりしないため、**予算 → 距離内の計画 → 実際の掃引区間での生成**は区別する。

既定値の計画器を固定シード123で1024発実行すると、予算は1536個で平均1.5個。うち距離上限6.75以内の計画は1152個、平均1.125個だった。この数字は固定の距離上限を与えた計画器だけの測定で、原作や実ゲームの発生率を測定したものではない。実ゲームへの統合は既存の回収上限と同じ60を計画上限に設定し、実際の弾道・地形衝突で打ち切る。そのため通常の割当ては距離6.75で事前に減らされず、実際の生成数は衝突した位置によって決まる。

割当て上限は1発12個、位相の最大数は16。通常の基準値では1個または2個の割当てになる。前段階の最大8個／弾という独自規則は、この計画器の8位相とは別の概念である。

## 単独テストと統合時の確認

`project/tools/ink_emission_pattern_tests.cpp` では次を確認した。

- 同じシード・入力から全計画項目を再現でき、Resetで状態も復元する。
- 1024発の小数予算は1536個。1個割当て512回、2個割当て512回になる。
- 任意の連続8発で8区画を重複なく使う。巡回境界や射撃停止・再開の位置に依存しない。
- 計画距離は昇順で距離上限以内。幅、横ずれ、足元の位置は指定範囲内に収まる。
- 乾いた接地状態の射撃が続いても、救済待ちは最大4回に収まる。
- 足元が塗れている、または空中なら救済を要求しない。
- 負値、0、大きすぎる値、NaN、無限大、実行中の設定変更でも固定配列を超えず、有限の正のブラシ入力を返す。

単独テストは形状の範囲と計画器の性質を調べるものであり、現実の塗装面に連続した道ができることの証明にはしない。統合後は主弾の実際の飛行、落下飛沫、面への衝突、CPU所有者マスクまで通した追加検証を実行した。25種類の射撃履歴と5方向を組み合わせた125条件すべてで、1秒連射後に足元から着弾付近まで4近傍の塗装セルが連結した。同じ条件を1.15秒でも確認し、125条件すべてで接続した。標準の25条件の連結回帰テストも成功した。射撃乱数が飛沫の外観設定から独立する回帰テストを維持している。
