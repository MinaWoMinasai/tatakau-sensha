# Ink Shooter Lab 第4段階：レティクル・ストリンガー・複数ブキ

実装日: 2026-09-12。既存の塗り・人型移動・イカ変身・遊泳を引き継ぎ、ブキの切替と編集を追加した。原作値の基準は前段階と同じ Splatoon 3 対戦用 Ver.11.3.0。最新版への一致を意味しない。

## 操作

```powershell
# Development の日本語設定画面から開始
.\project\tools\run_ink_shooter.ps1 -Settings
# 35秒の追加ブキ・レティクル検証
.\project\tools\run_ink_shooter.ps1 -Weapons
# 6組のCPU回帰テスト
.\project\tools\test_ink_simulation.ps1
```

| 入力 | 動作 |
|---|---|
| 1 / 2 | シューター / トライストリンガー参考へ切替 |
| Q | 登録した順に次のブキへ切替 |
| 左クリック | シューターは長押し連射。ストリンガーは押して溜め、離して1射 |
| Space | ジャンプ。空中でストリンガーを離すと縦撃ち |

## レティクル

添付の `レティクル.mp4` をフレーム抽出して観察した。中央の小円と点は一定サイズ、外側の4本の斜線は射撃・ジャンプによる現在の拡散値に連動する。動画で目立つ横方向の変化を採用し、縦方向の帯は基本サイズを保つ。

画面サイズとカメラ視野角から角度をピクセルへ投影する。中央円を一緒に拡大しない。ストリンガーは横／縦の発射方向、1〜3本のマーカー、2段階のチャージリングを表示する。満チャージでは収束する。インク不足では赤く表示する。

これは拡散角の表示であり、重力・壁への衝突まで追った着弾予測や射程内の敵へのロック表示ではない。動画と同じHUD内部定数・カメラ設定を断定していない。根拠と投影テストは [レティクル調査](ink_phase4_reticle_research.md)。

## トライストリンガー参考

地上は横3矢、空中は縦3矢。短押しも1射として扱い、押しっぱなしの満チャージで自動連射しない。30F／72Fで1段階／最大となり、1段階以降は地形に刺さった矢が45F後に破裂する。3D表示にも弓・引く弦・チャージの光・残った冷却矢・爆発を追加した。

| 性能 | 最小 / 1段階 / 最大 |
|---|---|
| 基準チャージ | 9 / 30 / 72F |
| 1矢の直撃ダメージ | 30 / 35 / 35 |
| 1射のインク消費 | 5 / 6 / 8.5% |
| 拡散角 | 8 / 8 / 0度 |
| 発射後硬直 | 12 / 15 / 15F |

爆発ダメージは30。直撃した矢はその場で消費し、同じ矢の地形爆発を重ねない。HP100の的に最大チャージ3矢が当たると105ダメージ相当となる。的の命中回数は矢・爆発ごとの回数であり、トリガーを離した回数とは異なる。

空中のチャージ速度は地上の1/3を採用した。これは公開データの版差分と公式のLACT-450変更内容からの推論。端点間の線形補間、空中短押しにも実時間9Fで応答する入力待機、発射時にまとめてインクを消費する処理はCG2の近似。足りないチャージ量で離した場合は不発となり、インク量に合わせた自動段階下げは行わない。

爆発は上下方向の位置補正を加え、的への地形遮蔽を確認する。爆発塗りは矢が付いた有限平面へ投影する簡易方式で、隣接するすべての壁・床へ塗りを配るものではない。弾道積分・飛沫の乱数や位相・塗りのブラシ・簡易モデルも独自表現を含む。調査の出典と確度は [ストリンガー調査](ink_phase4_stringer_research.md)。

## ブキを増やす

F1 の「ブキを選ぶ・作る」で既存ブキを選び、「複製して新しいブキを作る」を押す。日本語名と数値を編集し、「このブキで試し撃ち」で反映する。「ブキ一覧をファイルに保存」で `project/resources/configs/ink_weapons.json` へ保存する。

編集対象・試し撃ち中の装備・保存ファイルを分けた。編集対象の切替では有効な下書きを一覧に保持し、再読み込みは「未保存の変更を戻して再読込」の明示操作で行う。再読み込み後の使用中の装備は再適用まで維持する。移動や床の塗りはブキ適用時にリセットしない。

同じクラスのシューター／ストリンガー追加は複製と数値変更で可能。新しい攻撃方式のクラスを作る場合はC++側の挙動・検証・編集メタデータ・表示を追加する。JSONに未知のクラス名を書くだけでは増えない。ストリンガーは1〜3本に対応し、チャージキープは未対応として編集不可。

`WeaponDefinition` は安定ID・所有する日本語名・クラス・型付き性能を持ち、`WeaponCatalog` が検証と入出力を担当する。シミュレーションへ適用時に値をコピーし、さらに各弾と冷却矢にも発射時の性能を持たせる。途中で別のブキを装備しても、飛んでいる弾の物理・ダメージ・塗り・爆発が変わらない。

保存は同じフォルダーの一時ファイルを完成させてから置き換える。読み込みは一時カタログ全体を検証してから反映する。不正なJSON・未知キー・重複ID・数値不整合などで現在の一覧を失わない。現在の計算で使わない公開値は「参考」で読み取り専用にした。詳しい層構成と拡張手順は [ブキ編集基盤](ink_phase4_weapon_architecture.md)。

## 検証

CPUテストは従来の移動・射撃・塗り、飛沫計画、チャージ計算、ストリンガー統合、ブキカタログ、レティクル数学の6組。チャージ取消、切替後の発射済み矢、壁・床の爆発、20秒の反復と寿命終了、114項目の保存・再読込、不正入力と保存失敗時の保持を含む。

Development / Release の x64 ビルドは成功。両構成で35秒・8区間のネイティブ自動操作を実行し、起動時を含めたD3D12 InfoQueueのエラー0件・警告0件を確認した。D3D12デバッグレイヤーは有効、GPU Based Validationは無効。GPUの全機種での動作保証を意味しない。

Release記録では、取消区間の発射0・冷却矢0・インク満タン、的の区間でHP0、床／壁の区間で冷却矢3から爆発後0への遷移を確認した。68点の記録FPSは平均56.1、範囲46.5〜58.1。画像保存・GPU読戻しを含む自動検証時の値で、通常操作の最大性能を測ったものではない。実行機はRTX 4060 Laptop GPU。

日本語の実画面から複製を作り、発射数を3→2へ変更して保存、下書きを3へ変えて再読込すると保存した2へ戻ること、適用するとHUDが横2本へ変わりレティクルの点の間隔も変わることを確認した。試験用コピーは検証後に除き、納品するカタログは基準の2ブキとした。長い日本語名も保存形式の240バイト上限を収められる入力欄とした。
