# 第5段階: 自インクから未塗装へ出るイカの慣性

2026-09-12。ユーザーの「自分のインクを出た瞬間に急減速するので、速度に余韻を持たせたい」という依頼に対応する。シューター・ストリンガー共通の移動処理だけを変更し、射撃・塗りマスク・インク回復の条件を維持する。

## 調査と再現の境界

[任天堂のSplatoon 3公式プレイ説明](https://splatoon.nintendo.com/ca/gameplay/)では、自分の色のインクに潜ることで高速移動・壁登り・補給が可能になると説明されている。[任天堂の移動に関する説明](https://splatoon.nintendo.com/en/news/up-your-game-in-splatoon-3-with-these-quick-tips/)でも、自色インクの移動と敵色インクでの移動制限が区別されている。これらは未塗装の境界で速度を何F残すか、摩擦係数がいくつかまでは公開していない。

固定11.3.0の一次解析データとして [LeannyのSplPlayerパラメータ](https://github.com/Leanny/splat3/blob/7280ff9cde8bb1c5dcef46c700c326471584d2e6/data/parameter/1130/misc/SplPlayer.game__GameParameterTable.json)も確認した。このファイルは一部の上書き値のみであり、今回の「自色床から未塗装へ出たイカ」の減速式を特定できなかった。`PlayerPipelineParam.MoveAcc` など別の移動機構の数値を通常のイカ移動へ転用していない。一般の検証Wikiにある慣性キャンセル・加速の説明は調査の手掛かりとしたが、今回の専門数値の根拠にはしていない。

したがって、以下の減速9.0、最大0.60秒、制動倍率2.2はすべて **CG2の調整値**。原作の確定した摩擦係数やフレーム値とは主張しない。既存の距離縮尺は維持し、CG2の距離単位を実世界のメートルとは扱わない。

## 変更前の原因

`Simulation::MovePlayer` は、潜伏を抜けたときと未塗装へ接地したtickの両方で水平速度を `drySquidSpeed` まで即座に制限していた。そのため既定の遊泳速度5.76から未塗装速度0.9へ一度の更新で落ち、狭い塗りの切れ目でも急停止したように見えていた。

## 動作

自色の床を泳いだまま未塗装へ出た場合だけ、`drySquidCarryRemaining_` を開始する。境界を横切ったtickでは現在の水平速度を保ち、次の更新から乾いた床での入力速度へベクトルとして近づける。過去の速度を加算し直す処理は持たない。壁で消えた速度、入力を離して消えた速度、すでに減った速度は復活しない。

| 条件 | 動作 |
|---|---|
| 自色床のSwim→未塗装のSquid | 現在の水平速度を引き継ぎ、減速を開始 |
| 前方向を押し続ける | 0.9の通常移動へ滑らかに減速 |
| 入力を離す | 停止へ強く減速 |
| 逆方向へ入力する | 現在の進行方向を制動してから向きを変える。逆向きへ高速で瞬間反転しない |
| 横へ入力する | 現在速度から新しい低速入力へ近づけ、余剰速度を増やさない |
| 短い切れ目を渡って再入水 | 慣性状態を終了し、通常の遊泳加速で既存の最高速度へ戻る |
| 敵色へ接地 | そのtickで敵色の速度制限を適用し、余韻を終了 |
| 壁・段差と衝突 | 既存の衝突で法線方向の速度を除去。保存速度からの復活はない |
| 壁泳ぎ・人型化 | 床上の余韻を終了し、それぞれの移動処理へ戻る |
| ジャンプ・崖から空中へ出る | 床上の余韻タイマーを終了。既存の空中速度保持を利用し、乾地からのジャンプはその時点で残っている速度を継承 |
| 未塗装への着地 | 新しい余韻を発生させず、通常の乾いた床の速度へ制限 |
| ステージリセット・位置移動 | 余韻をクリア |

塗り判定は本当に接触している面のCPUマスクを使う。余韻が残っていても、自色を出た瞬間から状態は露出イカであり、高速補給や隠れた状態にはしない。移動がインクを勝手に塗ることもない。

## 調整項目

`MovementParams` に追加。武器ごとの保存値ではなく共通移動の調整値。

| C++名 | 日本語表示案 | 既定値 | 単位 |
|---|---|---|---|
| `drySquidCarryDeceleration` | 未塗装へ出た後の減速 | 9.0 | 距離/秒² |
| `drySquidCarryMaxTime` | 未塗装での余韻の上限 | 0.60 | 秒 |
| `drySquidCarryBrakeMultiplier` | 入力なし・逆方向の制動 | 2.2 | 倍 |

`DrySquidCarryRemaining()` はデバッグ表示用の残り秒数。残り時間を直接速度として使ったり、定数の最高速度を足し戻したりしない。

減速の設定を小さくしすぎても永続しないよう、残り時間で入力速度へ到達できる最低限の減速を毎tickから適用する。最後のtickだけ速度を切る処理ではない。最大時間0は従来どおり余韻なしにできる。

既定の速度5.76から前進し続ける場合、連続時間での目安は0.1秒後4.86、0.3秒後3.06、約0.54秒後0.9。実処理は120Hzなので境界検出と積分に1tick以内の差がある。約0.45距離の短い切れ目を、速度を残したまま渡れる。

## 検証

新規 `project/tools/ink_movement_carry_tests.cpp` を `InkSimulation.cpp` と `InkSimulation.Stringer.cpp` にリンクし、MSVC C++17 `/utf-8 /W4 /O2` で7グループPASS。

- 実マスクの境界を出たtickで速度が連続し、その後は期限までに減速する。
- 0.45距離の未塗装の切れ目を渡って再入水し、速度の加算や無料塗りがない。
- 入力解除・逆向き・90度の方向変更で停止や旋回ができ、速度が増えない。
- 敵色の即時制限、壁での停止、壁泳ぎへの切替、人型化を維持する。
- 既存の遊泳ジャンプと崖からの水平速度を維持し、余韻中のジャンプは現在速度を引き継ぐ。未塗装への着地で永続しない。
- 8個以上の切れ目を連続で渡っても最高速度を超えず、位置移動・リセットで状態を消す。
- 60/120/240Hzで減速速度が一致し、距離の差が0.03以内。余韻0、極めて弱い減速設定も検証する。

既存 `ink_simulation_tests.cpp` の旧「塗りを出ると即速度制限」の1件は新要件へ更新し、時間経過後に乾地速度へ戻る条件を追加した。既存スクリプトの射撃・塗り・遊泳・壁・ストリンガー・JSON・照準の6suiteもすべてPASSを確認した。音のイベントやネイティブ画面の見た目の検証は親担当。
