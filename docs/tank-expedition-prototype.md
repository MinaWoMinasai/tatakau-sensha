# 分岐遠征（試作 v2）の遊び方

短い戦闘を終えるたびに改造を選び、報酬の違うルートを進む、5戦闘の試作モードです。HP・機体・主軸コア・取得した改造・整備を持ち越し、最後のボス撃破を目指します。v2では突進兵と狙撃兵、機体ごとの進化二択、報酬画面での整備、オリジナルのBGM・SEを追加しました。

## 起動

リポジトリのルートから、ビルド済みのゲームを起動します。

```powershell
.\project\tools\run_tank_expedition.ps1
```

通常のタイトルでは先頭の「分岐遠征（試作）」を選ぶか、F9を押します。上下キー／W・Sで項目を選び、Enter／Space／クリックで決定します。従来の「コア争奪戦」はタイトルのF10、または `run_tank_run.ps1` で引き続き起動できます。フリープレイ、チュートリアル、F8の既存モードも残っています。

既定はDevelopment版です。Release版は `-Configuration Release` を指定します。Debug指定で実行ファイルがない場合はDevelopment版を使用します。未ビルドの場合は、Visual Studioで `project/CG2.sln` を対象構成・x64でビルドしてください。

## 遠征の流れ

開始時に3種類の機体と3種類の主軸コアから選びます。戦闘を終えたら、表示される改造候補から1枚を選んで進みます。報酬は資材を消費せず、選択を済ませるまで次の戦闘は始まりません。

| 順番 | 内容 | クリア後 |
|---|---|---|
| 第1戦 | 通常戦 | 改造を選び、資源ルート／精鋭ルートへ分岐 |
| 第2戦 | 護衛撃破後の資源争奪、または精鋭戦 | 改造を選び、イベントと機体進化へ |
| 第3戦 | 狙撃兵の多い反射ルート、または突進兵の多いドローンルート | 系統に合う改造を選ぶ |
| 第4戦 | 3つの制御装置と護衛の制圧 | レア候補のある改造を選ぶ |
| 第5戦 | ボス戦 | 撃破で遠征クリア |

精鋭戦と第4戦の報酬には、未所持のレア改造が残っていればレア候補が含まれます。反射ルートでは「反射コーティング」、ドローンルートでは「援護ドローン」が未所持なら候補に入ります。取得済みの改造は重複して提示されません。主軸コアや改造の基本効果は、[コア争奪戦のガイド](tank-run-prototype.md)に記載しています。遠征のドローン進化では、後述の機数・追加機数を使います。

資源ルートでは、まず突進兵と狙撃兵の護衛を倒します。護衛を全て倒してから金色のコアが出現し、ライバルとの争奪が始まります。コアを自分が確保するとHPが8回復し、部屋の改造報酬にレア候補が含まれます。ライバルが確保した場合も次へ進めますが、この確保による回復とレア保証は得られません。

第2戦の後のイベントでは、次のどちらかを選びます。

- 修理：HPを40回復します。最大HPを超えては回復しません。
- 危険な取引：HPを20消費し、追加のレア改造報酬を受け取ります。HPが21以上あるときに選べます。20以下では消費せず、イベント画面に留まります。

イベントを済ませると機体進化を選び、反射／ドローンの次ルートへ進みます。通常の部屋報酬は4回、危険な取引を選んだ場合は追加分を含めて5回です。部屋を移ってもHPは全回復せず、取得した改造はボス戦まで持ち越します。

第4戦は、制御装置を3つ破壊し、さらに護衛も全て倒すと突破できます。制御装置は自分が壊すと1つにつきHPが8回復します。部屋移動ではスタミナを回復し、直前の弾・ドローン・移動速度を清算します。危険な壁の基本接触ダメージはこのモードでは12で、装甲整備の軽減対象です。

## 戦闘の読み方

攻撃する敵の残数と目標をHUDに表示します。攻撃しない四角形・三角形は任意の破壊対象で、通常戦の全滅条件には含めません。図形を残していても、攻撃する敵を倒せば通常戦を突破できます。最終戦はボスの撃破で終了します。

| 敵 | 行動と予告 | 反撃の機会 |
|---|---|---|
| 突進兵 | 遮蔽物を回り込んで接近し、矢印で進路を予告して突進。金色になった予告は方向が固定される | 横へかわす、壁へ誘う。壁やプレイヤーへの衝突後、または突進終了後に硬直 |
| 狙撃兵 | 射線が通る相手を追尾し、点線で照準を表示。金色になって照準が止まった後に単発射撃 | 固定された射線から外れる、遮蔽物を使う。射撃後の硬直に攻撃 |

両者とも「追尾する予告→固定された予告→攻撃→硬直」の順に行動します。硬直中は水色の表示になり、突進兵の接触ダメージもなくなります。部屋ごとに混成と地形を変えています。反射ルートは狙撃兵3体と突進兵1体、ドローンルートは突進兵3体と狙撃兵1体です。

## 進化と整備

第2戦後の進化は、開始機体の方向性を引き継いだ二択です。経験値による解禁は不要で、現在の機体で進む選択肢もあります。主軸・改造・整備・現在HPを引き継ぎ、進化自体では回復しません。遠征ではCキーの従来ツリーは開かず、中間地点で進化を選びます。他モードのツリーや機体設定は従来どおりです。

| 開始機体 | 進化先A | 進化先B |
|---|---|---|
| ツイン | **トライファン**：扇状の3砲を同時発射し、広い範囲を狙う | **ツインランス**：正面の2砲を同時発射。高精度・弾速45%増・1発の威力25%増 |
| マシンガン | **ストームガン**：2砲の高速交互射撃。発射間隔30%短縮・広い散布・1発の威力15%減 | **バンクショット**：高精度の壁反射弾。威力30%増・弾速20%増・発射間隔40%増 |
| オーバーシア | **スウォーム**：基本8機の軽射撃ドローン。各機の発射間隔10%短縮・各弾の威力20%減 | **アーティラリー**：基本3機の重射撃ドローン。各弾の威力2.7倍・弾速55%増・発射間隔15%増 |

指揮コアと援護ドローン改造による追加は、スウォームではそれぞれ2機、アーティラリーではそれぞれ1機です。両方を持つ場合の上限はスウォーム12機、アーティラリー5機です。表の倍率は開始機体の設定に対する値で、主軸・改造・整備の効果も重なります。

**機体整備は報酬画面のTabキー、または下部の整備ボタンから開けます。** 第1〜4戦を突破するごとに1ポイント、1回の遠征で合計4ポイントを得ます。イベントの追加報酬ではポイントは増えません。使わないポイントは次の報酬画面へ持ち越せます。

| 整備 | 1段階の効果 | 3段階の効果 |
|---|---|---|
| 1：機動整備 | 移動速度 +6% | +18% |
| 2：装填整備 | 発射間隔 -7%。主砲とドローンに適用 | -21% |
| 3：装甲整備 | 被ダメージ -8% | -24% |

各項目は3段階までです。数字キー1・2・3または項目の左クリックで1ポイント使用し、Shift＋数字キーまたは項目の右クリックで1段階戻してポイントを返します。報酬画面内で振り直せますが、整備・振り直しによってHPは回復しません。装甲は整数HPに丸め、元が1以上のダメージを0にはしません。イベントのHP20支払いは軽減しません。

整備後はTabまたは下部ボタンで改造の選択へ戻ります。改造を決定すると先へ進むため、必要な整備は決定前に行ってください。

## 音

独自合成のBGMを2レイヤーで再生します。15秒の同じフレーズを継続し、通常戦とボスで追加レイヤーの音量を変え、選択画面・一時停止中は小さくします。部屋を移るたびに先頭へ戻しません。

発射・命中・撃破・敵の予告・ダッシュ・プレイヤー被弾・強化確定にSEを割り当て、散弾や連鎖で音が重なりすぎないよう短い発音制限を設けています。ジャスト回避の成立には強化確定と同じ確認音を使います。素材名が `armor_break.wav` の音は現在プレイヤー被弾時に使っており、装甲兵や敵のコア露出の仕組みは今回の実装には含まれません。

**MでBGM、NでSEを個別にON/OFF**できます。一時停止画面に操作と現在の状態を表示します。外部音源は使用していません。音は試作品で、聴感や最終的な音量バランスの評価は未実施です。[音声素材・再生成・検証の詳細](../project/resources/audio/tank_expedition/README.md)

## 操作

| 操作 | 内容 |
|---|---|
| WASD／マウス | 移動／照準 |
| 左クリック長押し | 射撃。指揮機体ではドローンを操作 |
| 右クリック | ダッシュ。スタミナと待ち時間が必要 |
| Tab／報酬画面下の整備ボタン | 改造選択と機体整備を切り替える |
| 整備中の1・2・3／左クリック | 対応する整備に1ポイント使用 |
| 整備中のShift＋1・2・3／右クリック | 対応する整備を1段階戻す |
| メニューの候補選択 | 画面に表示されるキーまたはクリックで選択・決定 |
| Esc | 一時停止／再開 |
| M／N | BGM／SEを個別にON/OFF |
| F1 | 性能モニターを簡易表示／詳細表示／OFFに切り替える（Releaseでも利用可能） |
| Shift＋F1 | CPU更新／GPU全体／描画パス／描画量を切り替える |
| 結果画面 | リトライ、またはタイトルへ戻る |

改造・整備・分岐・イベント・進化の選択中は戦闘と戦闘時間が停止します。このモードは部屋の終了時に強化を選ぶため、コア争奪戦の「資材を貯めてEで購入」とは進め方が異なります。Cキーからの進化は使わず、中間地点で選びます。

60 FPS上限制御は起動時から有効です。性能表示の読み方・完全無効化・最適化の検証結果は[性能モニターの説明](tank-performance-monitor.md)を参照してください。

リトライは新しい遠征の開始です。HP、取得した改造、進化、整備ポイントと配分、ルートの履歴をリセットして、機体と主軸から選び直します。恒久的な能力強化はありません。

## テスト

単体テストには既存のVisual Studio C++ツールが必要です。リポジトリのルートで実行します。

```powershell
# 全ルート、報酬、目標条件、進化6種、整備ポイントと振り直し
.\project\tools\test_tank_expedition.ps1

# 敵の予告・固定・攻撃・硬直と遮蔽物周辺の経路
.\project\tools\test_tank_enemy_combat.ps1

# 既存のアリーナ進行・ボス攻撃・改造倍率
.\project\tools\test_tank_run.ps1

# ビルド済みゲームで自動確認。新しい結果の合否まで待つ
.\project\tools\run_tank_expedition.ps1 -Validate -Variant 0 -Wait

# 6シナリオを順番に実行する。並列起動しない
0..5 | ForEach-Object {
    .\project\tools\run_tank_expedition.ps1 -Validate -Variant $_ -Wait
}
```

単体テストは、2回の分岐とイベントを組み合わせた全8経路、5つの戦闘、修理経路4回／取引経路5回の報酬、選択中の時間停止、死亡・クリア・再開始を検証します。報酬の候補生成は、乱数シード、系統の指定、レア保証、取得済み候補の除外、候補の枯渇と取得上限を確認します。v2では、図形を除いた全滅判定、護衛と装置の両方を求める制圧条件、進化6種、整備の4ポイント上限・段階上限・繰り返しの振り直しも対象です。

`-Variant` を0〜5に変えると、次のシナリオを実行します。開始機体・主軸の選択番号は `[0, 2, 0, 1, 1, 2]`、進化の選択番号は `[0, 0, 1, 0, 1, 1]` です。最初の分岐は `Variant % 2`、次の分岐は `floor(Variant / 2) % 2`、イベントは `Variant % 3 == 0` のとき修理を選びます。

| Variant | 開始機体・主軸 | 進化 | 経路と確認内容 | 改造報酬の回数 |
|---|---|---|---|---|
| 0 | ツイン・反射 | トライファン | 資源を自分が確保 → 修理 → 反射ルート | 4回 |
| 1 | オーバーシア・指揮 | スウォーム | 精鋭 → HP20を払って追加改造 → 反射ルート | 5回 |
| 2 | ツイン・反射 | ツインランス | 資源をライバルが確保 → HP20を払って追加改造 → ドローンルート | 5回 |
| 3 | マシンガン・突撃 | ストームガン | 精鋭 → 修理 → ドローンルート | 4回 |
| 4 | マシンガン・突撃 | バンクショット | 資源を自分が確保 → HP20を払って追加改造 → 反射ルート | 5回 |
| 5 | オーバーシア・指揮 | アーティラリー | 精鋭 → HP20を払って追加改造 → 反射ルート | 5回 |

どのシナリオも第4戦の装置・護衛制圧と第5戦のボスまで進めます。プレイヤーへの通常ダメージを無効化し、自動選択と敵・コアへの強制ダメージで進行を確認します。イベントのHPコストは検証中も適用されます。整備の使用・返却・再使用でHPが変わらないこと、進化でHP・改造・整備を保持することも確認対象です。

`-Validate` は子プロセスに `CG2_TANK_AUTOTEST=1` と `CG2_TANK_EXPEDITION_VARIANT` を渡します。非表示で自動シナリオを実行し、完了時にゲームが閉じます。`-Wait` を併用すると最長180秒待ち、終了コードと起動時刻より新しい `validation.json` を確認します。5部屋の完了、検証エラー0、整備4ポイント使用・残り0、音声9素材ロード・BGM再生中を満たさない場合は失敗として終了します。`-Wait` なしでは起動後すぐに戻ります。

レンダラのキャッシュと保存領域を共有するため、検証の並列実行には対応していません。既存のゲームが終了している状態で、上記の `-Wait` 付き手順を順番に実行してください。

2026-09-19の確認では、Development／Releaseの両構成をビルドし、Development版の全6シナリオが上記の実機自動確認を通過しました。全シナリオで5部屋を完了し、整備4ポイント使用・残り0、検証エラー0、音声9素材のロードとBGM再生を確認しています。2回のルート分岐の全4組み合わせ、修理・取引、自分・ライバルによる資源確保を含みます。

Release版の通常起動では、機体・主軸のクリック選択、敵の攻撃によるHP減少、敗北画面への移行、クリックによるリトライと機体選択への復帰を確認しました。実画面で見つけた開始時の古いCキー進化案内も修正しています。一時停止とM／Nのキー操作、音の聴感、戦闘バランスは人による試遊確認が残っています。

出力先は `project/generated/tank_expedition/variant_N/` です。`N` は指定した0〜5の番号です。

- `validation.json`：起動時に `completed: false` を書き、クリア確認後に `completed: true`、到達部屋数、ルート、イベント、報酬回数、HP、進化先、改造一覧、整備段階・残りポイント、検証エラー数、音声ロード数・発音回数・BGM再生状態を保存します。結果を見る際は更新日時も確認します。
- `choice_N.png`：機体・主軸・報酬・分岐・イベント・進化の選択画面を順番に保存します。
- `maintenance_N.png`：第1〜4戦後の整備画面です。
- `room_N.png`：第1〜5戦の画面です。
- `result.png`：クリア結果画面です。

通常起動では両方の検証用環境変数を外し、どちらの場合も起動後に呼び出し元の値を復元します。

自動確認は画面遷移や報酬の持ち越しを調べるためのもので、敵の倒しやすさ、適切な戦闘時間、ビルド同士の強さ、音の聴感を評価するものではありません。試遊では「予告を見て移動したくなるか」「敵の組み合わせで倒す順番が変わるか」「進化や改造で動き方が変わるか」「整備で弱点を補えるか」「選択画面が戦闘の勢いを切りすぎないか」を確かめてください。
