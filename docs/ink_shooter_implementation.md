# Ink Shooter Lab 実装報告

2026-09-12。CG2 上に、**撃つ → 床・壁が塗れる → 自分のインクへ潜る → 高速移動・補給 → 人型へ戻って射撃**を行えるテストシーンを追加した。任天堂のモデル、テクスチャ、音声、ゲームコードは使用していない。既存の CG2 描画・入力・シーン切り替えを利用し、独自の仮キャラクターと塗りを構成している。

起動はタイトル画面で **F8**、またはビルド済みの Development 実行ファイルに対して以下のスクリプトを使用する。スクリプトはビルドを行わない。

```powershell
# ワークスペースのルートで実行
.\project\tools\run_ink_shooter.ps1

# 約12秒の操作デモから開始
.\project\tools\run_ink_shooter.ps1 -Demo
```

| 操作 | 入力 |
| --- | --- |
| 人型・遊泳の移動 | WASD |
| カメラ・照準 | マウス |
| フルオート射撃 | 左クリック長押し |
| 自分のインクに潜る | Shift長押し |
| ジャンプ・壁から離脱 | Space |
| 壁を泳ぐ | 塗った壁へ近づき、Shift＋W/S/A/D |
| マウス拘束の切り替え | Tab |
| 調整・デバッグ画面 | F1（ImGuiを有効にしたビルド） |
| ステージ・インク・プレイヤーのリセット | R（操作中） |
| 自動デモの開始・停止 | F9 |
| タイトルに戻る | Esc |

Tabによるマウス解放は入力を止めるもので、ゲーム時間全体の一時停止ではない。調整値は実行中のメモリに反映し、ファイルへ自動保存しない。

## 1. 調査した Splatoon 3 の仕様

公式で確認できた最新の **Ver.11.3.0（2026-08-20配信）**を基準に、対戦用スプラシューター、ギアなしのパラメータを調べた。主な基準は6フレームごとの連射、1発0.92%のインク消費、射撃後20フレームの回復停止、地上4.86°・ジャンプ直後11.66°の拡散、自インクでの高速移動と補給である。[任天堂 更新データ](https://support.nintendo.com/jp/switch/software_support/av5ja/index.html)

時間は原作の60 Hz、生データ距離1をCG2距離0.5として換算した。録画30 fpsの参考動画から数値を測定していない。動画では弾道の下の飛沫、伸びと膨らみを持つ輪郭、小粒の飛散、連続した道、壁の塗りを視覚的に参考にした。正確な原作値・共通初期値・独自近似の区分は[調査文書](ink_shooter_research.md)にまとめている。

## 3. 採用した方式

`INK_SHOOTER_LAB`という独立した組み込みシーンを追加し、ゲームロジックをDirectX非依存の`ink::Simulation`へ分離した。シーンは入力、三人称カメラ、仮キャラクター、HUD、描画を担当する。ゲームロジックは **120 Hz固定刻み**で更新し、描画の経過時間を累積する。

テストステージは有限の長方形面16枚で構成した床、坂、壁、上段、非塗装パネル。床を坂・台の位置で分割し、下に見えない床が残って誤接地・誤潜伏することを防ぐ。弾と飛沫は掃引衝突を使い、GPU描画とCPUの自色判定には同じ面ID・楕円スタンプを渡す。

仮キャラクターはCG2で生成した箱・球の組み合わせ。弾・飛沫は既存の線描画、文字は既存の`TextLabel`、調整画面は既存のImGuiを使用する。

## 7. 塗りの実装方法

GPU側に **2048×2048、RGBA8 UNORM** の永続UAV/SRVテクスチャを1枚持つ。4×4のアトラスで、各面に **512×512のタイル**を割り当てる。テクスチャ本体は約16 MiB。スタンプの囲い矩形だけを8×8スレッドのCompute Shaderで更新し、スタンプ間のUAVバリアと描画時の状態遷移で整合性を保つ。

CPU側にも各面 **512×512の1バイト所有者グリッド**を保持し、16枚で約4 MiB。同じ回転楕円・ピクセル中心の式で更新し、`GetInkAtWorldPosition`から自色を照会する。現在の実装はCPUだけ低解像度にしておらず、GPUと同じ判定粒度を使う。テクスチャ全体のCPU読戻しや毎フレームの全面アップロードは行わない。

0は未塗装、1は自色、2は別色の上書きを扱える。描画は現状2色のパレットを持ち、操作プレイヤーは1チームのみ。任意数のチームをそのまま表示できる構成とはしていない。

一つの塗り跡は中央楕円と複数の小さな楕円の合成。飛行中の落下飛沫も実際の衝突後にスタンプを追加する。GPUだけで輪郭ノイズを加えてCPU判定と塗り範囲がずれないようにしている。インクはリセット・シーン終了まで残り、ディスクへの保存は行わない。

床・坂・壁は同じ面UV方式を使用し、非塗装面は描画と判定の両方で拒否する。塗装面の輪郭の陰影と低い粗さにより濡れた見え方を付け、既存の色・法線・材質MRTへ出力する。

## 8. 人型移動

通常速度は **2.88/秒**、射撃中は **2.16/秒**。WASDはカメラの水平方向を基準にし、斜め入力を正規化する。加減速、重力、ジャンプ、有限面への接地、坂の高さ追従、壁による移動制限を実装した。プレイヤー重力20/秒²、ジャンプ初速7/秒、移動半径0.28などはCG2用の調整値。

カメラは後方・少し右の三人称。地形との接触時はカメラ距離を詰める。カメラ中心のレイと地形の交点を求め、銃口からその点へ射撃方向を補正する。弾の拡散と落下による実際の着弾差は残る。画面の照準に加え、銃口前方の遮蔽物の交点を補助表示する。

## 9. 遊泳移動

Shiftを押し、自分のインク上にいる間は遊泳状態へ入る。速度は **5.76/秒**、移動衝突半径は **0.16**。射撃中・射撃直後の制限中は潜らず、射撃入力で人型へ出る。見た目の切り替えは0.12秒の補間を使う。

自インクから地上の未塗装面へ出ると人型に戻り、そのフレームで地上速度を人型上限へ抑える。ジャンプ時は一度水平慣性を残して離陸できる。高速補給は自インクに接する遊泳状態でのみ有効。人型は10%/秒、自インク中は約33.333%/秒で回復し、最後の射撃後の回復停止を尊重する。

## 10. 壁移動

壁の接近判定、自色照会、壁面法線による吸着、上下左右の接線移動を実装した。Shift＋W/Sが上下、A/Dが左右。壁泳ぎ速度は **4.32/秒**の調整値。塗れていない部分へ進もうとすると吸着を解除する。

壁の上端に到達したときは向こう側の実際の天面を確認して乗り越える。Spaceは壁から外向き・上向きへ離脱する。対応対象は今回の有限平面ステージで、曲面・入り組んだ任意メッシュや天井への遊泳、イカノボリのチャージ動作は未実装。

## 11. ジャイロ対応状況

**センサーバックエンドは未実装。** デバッグ画面には利用不可と表示し、角速度は欠測表示にする。マウスだけで全ゲーム操作が可能。

調査ではGameInput v2の`GetSensorsState`、SDL3のGamepad Sensor API、Steam Inputの`GetMotionData`を比較した。Steamに依存しない次の候補はSDL3の入力専用導入。センサー存在確認、明示的有効化、rad/sの取得、較正・感度・反転・デッドゾーン・平滑化・リセンターの追加が必要で、これらの設定を実装済みとはしていない。[SDL3 センサー取得](https://wiki.libsdl.org/SDL3/SDL_GetGamepadSensorData) / [Microsoft GameInput v2](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/input/gameinput/interfaces/igameinputreading/methods/igameinputreading_getsensorsstate) / [Valve Steam Input](https://partner.steamgames.com/doc/api/ISteamInput)

## 13. 残っている問題・制約

- 原作の完全再現ではない。飛沫の個数・配置、輪郭、拡散の確率分布、壁移動や変身、カメラは独自近似を含む。
- 塗れる地形は16枚の有限長方形面が上限。任意の三角形メッシュ・可動地形・曲面へ一般化していない。
- 実際にダメージを与える標的、敵、対戦、サブ・スペシャル・ギア効果・イカフローはない。
- 弾の近似照準と実際の放物線・拡散には差がある。正確な弾道予測照準は改善余地がある。
- マスクは各面512²固定で、大きな面では輪郭の画素粒度が見える。スタンプごとのCompute dispatch・UAVバリアも、大量射撃へ拡張する際の調整対象。
- ジャイロ入力とセンサー設定は未実装。塗りと実行時調整値のディスク保存もない。
- 最終表示はDevelopment実行ファイルで再確認済み。仮モデルや塗りの輪郭・反射表現は改善余地がある。

## 14. 次に改善すべき項目

1. 動画の形状へ近づけるため、弾の進行方向・着弾角度によるブラシの伸びと、足元救済飛沫の条件を改善する。
2. 原作の連射時の外側確率、停止後の精度、ジャンプ精度の分布をサンプル可視化して調整する。
3. 壁の角・上端・坂での移動をさらに検証し、必要な地形から三角形メッシュ衝突へ拡張する。
4. 長時間の連射・複数発射源でGPU時間とCPUマスク更新を測り、スタンプのまとめ処理を検討する。
5. 基本ループを維持したまま、センサー搭載コントローラーを実機確認してSDL3ジャイロ入力を追加する。
